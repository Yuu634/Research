# 演奏難易度属性の改良案：算出式レビュー

作成日：2026-09-30
状態：**2026-09-30、ユーザーが「一旦この算出式で３以降のタスクを進めてください」と承認。**

ユーザーの「作成した属性算出式を人目で確認するフェーズを通してから、3以降を進める」という指示に従う。
算出式の説明・確認フェーズを経て実装に進んだ。以下は実証済みの難易度モデルではなく、検証可能な提案である。

## 1. 提案の概要

既存5属性を改良し、6番目に「リズムパターンの複雑さ」を**検証用の追加ラベル**として作る案を推奨する。
身体的な負荷と、パターンを理解・記憶する複雑さは分けて保存する。総合難易度へ加算する式は今回作らない。

| 属性 | 提案する意味 | 主な変更 |
|---|---|---|
| s_tech | 奏法・強弱制御の負荷 | 全音符に対する割合から、特殊打撃と同一楽器の強弱変化の秒当たり量へ |
| s_indep | 手足の非同期打撃の負荷 | 片方しか演奏しない場合を0とし、両者の活動量も反映 |
| s_hand | 両手合計の打撃負荷 | 1拍区切りの最大数から、平均密度と短い打撃間隔の両方へ |
| s_foot | ペダル別の打撃負荷 | KickとHHペダルを別々に測り、負荷の大きい方を採用 |
| s_move | 2本の手で必要になる最小の移動負荷 | 同時打撃・手の分担・秒単位の時間を考慮 |
| s_rhythm（候補） | 小節内のパターンの反復の少なさ | 固定長の打点系列のLZ複雑度。テンポと強弱には依存させない |

「手の速度」は運指が不明なので両手合計の代理量と明記する。
「移動負荷」は無理のない実運指を復元した値ではなく、配置仮定の下での楽観的な下限である。
「リズムの複雑さ」も、シンコペーション・ポリリズム・読譜難度のすべてを測るものではない。

## 3. 既存処理で確認した問題

対象：[drum_difficulty_calculator.py](../src/data/drum_difficulty_calculator.py)

- s_techは特殊奏法数／全音符数。他の通常打撃を増やすだけで特殊奏法の値が下がる。Accentも一律に数える。
- s_indepは手足が同時でない時刻の割合。手だけ、または足だけでも1になり、手足の協調負荷と一致しない。
- s_hand、s_footは4つの固定拍の最大打撃数×BPM。拍内の集中と分散、拍境界をまたぐ連打を区別しにくい。
- 足の2種類を合算し、別々のペダルに分散した打撃を単一ペダル連打と区別しない。
- s_moveは全手打撃を1列につなぎ、隣接トークンを同じ手が演奏するように比較する。秒でなくposition差で割るためテンポが反映されない。
- s_moveは同時刻の打撃の並び順によって、次の打撃との比較対象が変わり得る。
- 基準モデルは5属性・各8クラス。新しい6属性目は現行モデルでは条件入力として使用されない。
- 現在の収集pklのbar_positionsは各小節の開始点で、終端番兵を必ず含む形式ではない。旧ラベリングCLIのlen(bar_pos)-1ループをそのまま使うと末尾小節を落とす危険がある。

## 4. 共通の入力規約

主ラベルは、学習入力と対応を取れるよう**収集済みstandardトークンから算出**する。
このプロファイルは4/4、1拍24分割、1小節96位置。拍位置をq、実時間をtとする。

\[
t(q_2)-t(q_1)=\int_{q_1}^{q_2}\frac{60}{B(q)}\,dq
\]

Bはトークンで表現されたBPM。同一小節で一定なら \(\Delta t=60\Delta q/B\)、小節長は \(T=240/B\) 秒。
トークンの60〜240 BPM・5刻みへの変換をそのまま使うため、厳密な元演奏の速度ではなく**モデル表現上の負荷**を測る。
元MIDIのテンポと強弱は監査に残すが、モデルに見えない情報を教師値だけへ混入させない。

- 原譜の小節・拍位置を保持する。テンポ変化、前小節からの間隔、末尾小節、空小節を明示的に扱う。
- 手の楽器集合H、Kick K、HHペダルPの対応は現行の楽器分類を踏襲する。HH開閉から足の運動を追加推測しない。
- 秒時刻が同じ打撃をグループ化する。手足の一致判定は量子化後の位置で行い、トークン順に依存させない。
- 表現が確認できないフラム、ロール、チョーク、運指は新たに推測しない。
- 小節に音がなければ全属性0。計算不能と無音を同じ0にしない。
- 同一位置・同一打点の重複や同時に3つ以上の手打撃などは監査フラグを付ける。実演不能と断定せず、量子化や複数トラックの重畳も疑う。
- 旧式v1は残し、新式は別バージョンv2として実装する。

## 5. 5属性の算出式案

### 5.1 s_tech：奏法・強弱制御負荷

各打撃iに特殊打撃フラグ \(a_i\in\{0,1\}\) を付ける。
候補は、明示されたGhost、Snareのrim系、Ride Bell、明示されたFlam／Roll／Choke／Xstick。
複数に該当しても1回と数え、通常Accentのみではフラグを立てない。GM音高から実際の奏法を断定しない。
Rollトークンの内部打撃数は不明なので、1イベントとして記録し、その限界を付記する。

強弱はGhost=0、Normal=0.5、Accent=1の順序値 \(u_i\) を用いる。
同じ打点群で直前の打撃との強弱差を \(\delta_i=|u_i-u_{\mathrm{prev}(i)}|\) とする。
Snare/Rimは同一群、Ride/Bellは同一群、HH開閉は同一群とし、他は楽器群を分ける。
同一位置に同じ群が複数あれば、強弱遷移用の値はその最大値で代表する（特殊打撃の数は各イベントで数える）。このグループ集合をE_bとする。
直前は前小節まで参照し、なければ差0とする。強弱差の和は、打撃数ではなく「時刻×打点群」の各グループを1回ずつ数える。

\[
S_{\mathrm{tech}}=\frac{\sum_{i\in b}a_i+\lambda_{\mathrm{dyn}}\sum_{e\in E_b}\delta_e}{T},
\qquad \lambda_{\mathrm{dyn}}=1
\]

- 通常Kickを追加しても、特殊奏法を分母で薄めない。
- 一様な強打と、弱打・強打の切替を分ける。
- テンポが2倍なら、同じ記譜パターンの値は2倍になる。
- Ghostと強弱差には重複寄与がある。係数1は説明しやすい仮置きで、実証的な重みではない。
- 全強打の筋力負荷は測らない。MIDI velocityを打撃力の実測値と同一視しない。

### 5.2 s_indep：手足の非同期打撃負荷

HとFを、それぞれ手・足の打撃が存在する時刻の集合とする。
同時に2つの手打撃があってもHの1時刻と数える。\(N_H=|H|,\ N_F=|F|\)。

\[
A=\frac{|H\triangle F|}{|H\cup F|},\qquad
G=\frac{2\min(N_H,N_F)}{N_H+N_F}
\]

\[
S_{\mathrm{indep}}=
\begin{cases}
0 & N_H=0\ \text{または}\ N_F=0\\
A\,G\,\dfrac{|H\cup F|}{T} & \text{それ以外}
\end{cases}
\]

Aは非同期の割合、Gは両方の活動がある程度そろっているかを表す。
片手だけの演奏を「手足の独立性最大」と扱わず、同じ非同期パターンでも速い方を高くする。

この式は非同期の負荷の代理であり、完全同時打撃の協調、左右の手同士の独立性、
慣れたオスティナートと未知のポリリズムの差は直接測らない。
値0は「演奏が容易」の意味ではなく、「この指標で数える非同期負荷がない」という意味。

### 5.3 s_hand / s_foot：平均密度と局所的な速度

楽器集合Gについて、小節の打撃数を \(N_G\)、異なる発音時刻を \(t_j\)、その時刻の打撃数を \(m_j\) とする。
同じ集合Gの前の発音時刻との差を \(\Delta_j=t_j-t_{j-1}>0\) とする。
前小節の最後の発音も参照し、前の発音がない最初のグループは間隔統計から外す。

\[
D(G)=\frac{N_G}{T},\qquad
P(G)=Q_{0.9}\left(\left\{\frac{m_j}{\Delta_j}\right\}\right)
\]

\[
R(G)=\max(D(G),P(G)),\qquad
S_{\mathrm{hand}}=R(H),\qquad
S_{\mathrm{foot}}=\max(R(K),R(P))
\]

間隔が1つもない場合は \(P(G)=0\)。Qは線形補間の90パーセンタイルに固定する。
同時打撃はmで数え、0秒で割らない。平均負荷と短い区間の負荷の両方を残す。
最大値1点だけより外れ値に強くする狙いで90%点を選ぶが、短い小節では外れ値の影響が残る。
実装後には80%・90%・最大値の感度を報告し、人手レビューで固定した主式は勝手に差し替えない。

s_handは左右を区別しない合計負荷。両手交互か片手連打かはMIDIから確定できない。
s_footは単一Kick系とHHペダル系を別々に見る。ツインペダルによる負担分散は推測しない。
将来運指情報が得られた場合に、実際の四肢ごとの速度へ拡張できるよう生の構成値も保存する。

### 5.4 s_move：2本の手による最小移動負荷

現行DISTANCE_MATRIXを暫定の配置距離 \(d(p_i,p_j)\) として使う。
距離の最大は1で、実測メートルではない。China/Cowbell等の近似対応も設定に記録する。
これは指定文献から得たドラム配置ではなく、現行プロジェクトの仮定を引き継ぐもの。

前小節と対象小節の打撃を、2本の手へ割り当てる候補集合を \(\mathcal A\) とする。
同時刻の異なる打点は異なる手へ割り当てる。
同じ手の連続打撃について、後の打撃が対象小節に属する移動だけを評価する。

\[
S_{\mathrm{move}}=
\min_{a\in\mathcal A}\
\max_{\substack{i\rightarrow j:\,\mathrm{同じ手}\\j\in b}}
\frac{d(p_i,p_j)}{t_j-t_i}
\]

- 各手の最初の打撃に開始位置コストは課さない。移動対象がなければ0。
- 休符の間は移動できるものとし、直前の同じ手の打撃までの実時間を使う。
- 同じSnareとHHを両手で反復しているだけなら、架空の往復移動を作らない。
- 手の割当を全列挙せず、2本の手の最終打点・時刻を状態とする最小最大コストの動的計画法を予定する。
- 左右の交差、利き手、姿勢、開始位置、筋力、打撃速度との同時最適化は扱わない。

あくまで移動だけを最小化した下限なので、s_handとs_moveが同一の実運指で同時に達成できるとは保証しない。
同時に3打点以上などで割当不能なら欠損として記録し、0に置換しない。
5属性が必須の学習用pklには欠損を混ぜず、該当曲は理由付きで学習用出力から除外する案とする。
除外件数と理由を報告し、元トークンと途中の監査値は保持する。この扱いもレビュー対象。

## 6. 追加候補 s_rhythm：小節内の反復性

提案する6番目は、まず**テンポから独立した反復の少なさ**に限定する。
Kick、Snare/Rim、その他の3群について、1小節96位置の2値打点列 \(x_g\) を作る。
同時打撃数、velocity、音長を入れない。各小節を同じ長さで比べることで曲長の影響を避ける。

c(x)をLZ78のフレーズ数とする。辞書は小節・群ごとに空から開始し、
左から「まだ辞書にない最短の語」を1フレーズとして登録する。
最後に既出語だけが残った場合も末尾フレーズ1つとして数える。
\(n=96\)、\(x_0=0^{96}\) として、

\[
L(x)=\max(0,c(x)-c(x_0))\frac{\log_2 n}{n},\qquad
S_{\mathrm{rhythm}}=\frac{L(x_K)+L(x_S)+L(x_O)}{3}
\]

無音や全位置同じ値の列を基準に補正し、範囲を無理に0〜1へクリップしない。
これはRubricNetのPitch Set LZの再現ではなく、固定長ドラム打点列へ置き換えた**本研究のLZ78案**である。

- 同じ打点配置ならBPM・強弱を変えても不変。
- 同一群の音色置換や同時打撃の追加では変わらない。
- 反復の少ない並びを高くする仮説。ただし任意の音符追加で単調増加することは要求しない。
- 小節内だけの指標なので、4小節以上のフレーズ反復は別途見る必要がある。
- 安定したシンコペーションが高くなるとは限らない。LZだけで全リズム複雑性を説明しない。
- 密度や楽器群との相関は残り得るため、「音数とは完全に独立」とは扱わない。

### 6.1 採用前の診断計画

承認後、実装時に以下を行う。結果は別の実施記録に保存し、この式を結果に合わせて変更しない。

1. 等間隔、反復、同じ音数の非反復などの人工例で、定義どおりの数値か確認する。
2. Zenodoの拍単位の採譜データを同じ96位置へ写像し、最初の完全な4小節の平均を刺激ごとの値とする。
   音声の余分な終端拍や微小タイミングをこの主値に含めないことを明記する。
3. 40刺激のPerceivedComplexityとのSpearman・Kendall相関、刺激単位bootstrap区間を報告する。
   4,400試行を独立な4,400譜面として扱わない。
4. 資料に付属する音数・シンコペーション・BDM指標を対照として比較する。
   拍位置の量子化誤差、音数との相関も報告する。
5. この40刺激で都合よく式を変更しない。変更する場合は探索的な再設計として記録する。

LZ案が人の複雑さと合わない場合は「リズム難易度」として採用せず、反復性の記述子にとどめる。
その場合のシンコペーションとの複合式は、係数を自動で後付けせず再レビューする。

## 7. 手で確認できる例と、実装後の受入条件

以下は定義から計算した例で、データセットで検証した結果ではない。
時間は120 BPM・4/4・2秒とする。

| 例 | 旧式の問題／新式で確認すること |
|---|---|
| 手だけで打つ | 旧s_indep=1、新s_indep=0 |
| 手4打・足4打が完全同時 | 新s_indep=0。同期演奏そのものの負荷は他属性で見る |
| 手4打・足4打がすべて別時刻 | A=1、G=1、和集合8なので新s_indep=4 |
| 手を0, 0.5, 1.0, 1.5秒に1打ずつ | D=2、P=2なので新s_hand=2 |
| 手を0, 0.125, 0.25, 0.375秒に1打ずつ | D=2、P=8なので新s_hand=8。同じ4打でも集中を区別 |
| Kick4打とHHペダル4打が各々等間隔 | 新s_foot=2。合計8打を片足の速度として数えない |
| 同じ記譜でBPMを120から240へ | 新5属性は2倍（元が0なら0）、s_rhythmは不変 |
| 同時刻のSnare・HHのトークン順を逆転 | 全属性不変 |
| Ghost等を変えず通常Kickだけ追加 | s_techを全音符数で薄めない |
| 2つの固定打点を別々の手で反復 | s_move=0の割当が可能 |
| 3つの手打点が同時 | 移動の割当不能を記録。0点と偽装しない |
| 同じ入力のまま式を再実行 | 同じ生スコア・クラス・チェックサム |

さらに末尾の1小節、前小節からの連打、空小節、テンポ変化、
0値の多い属性、未知トークン、重複打撃をテストする。
Q90、特殊奏法係数、配置距離、LZの系列化は、特に人目で確認してほしい設計判断である。

## 8. 承認後に実施するラベリングの仕様案

対象は前タスクで収集したLakh・Groove・Groove2Grooveのdrum_collection_v1を想定する。
旧基準モデル用のprocessed_newデータは上書きしない。

現在の有効分割リストは計83,602曲：
- train：65,163
- val：8,658
- test：8,669
- itest：1,112

105,477個の全トークンpklには重複等で分割対象外のものもある。
今回は有効分割のIDを処理対象とし、追加の品質除外は理由・件数・IDを残す。ランダムに再分割しない。

予定出力：
- data/processed/drum_collection_difficulty_v2/：ラベル付きpkl
- data/metadata/drum_collection_difficulty_v2/：式バージョン、語彙参照、境界値、分割、原データ対応、監査
- output/revise_attribute_v2/：検証集計・診断結果

既存pklのbar_positionsとtoken_indicesをそのまま保持し、全実小節にdifficulty_classesを対応させる。
互換出力は(bar_positions, token_indices, difficulty_classes)の3要素形式。
生の連続スコア・構成値・欠損理由は別メタデータに残す。

クラス境界の案：
- 各属性0値はクラス0として分離する。
- 正値はtrainだけから7群への分位境界を推定し、クラス1〜7へ対応させる。
- データセット3種を等重み、各データセット内の曲を等重み、曲内の小節を等重みとする。
