## 目的関数

図の4項を使い、値が高い候補を優先する。

\[
J=-\lambda_d L_{\mathrm{difficulty}}
  +\lambda_s S_{\mathrm{skeleton}}
  -\lambda_r N_{\mathrm{rules}}
  -\lambda_e L_{\mathrm{edit}}.
\]

確認用の初期係数は次のとおり。学習・比較実験で選んだ最良値ではない。

| 項 | 初期係数 | 意味 |
|---|---:|---|
| 難易度の誤差 | 1.0 | 目標難易度に近いほど高評価 |
| 骨格類似度 | 0.5 | 元譜面の主要な打点を保つほど高評価 |
| 適用ルール数 | 0.02 | 同じ結果なら短いルール列を優先 |
| 編集距離 | 0.1 | 同程度の難易度・骨格なら変更の少ない候補を優先 |

`ScoreConfig`で4係数、5属性の重み、骨格4成分の重みを個別に設定できる。
係数・重みは有限・非負とし、成分の重みは合計が正であることを確認する。

### 難易度一致

承認済みv2の5属性を再計算し、保存済みのtrain由来クラス境界で0〜7へ変換する。
正規化値は `d_k = class_k / 7`。

\[
L_{\mathrm{difficulty}}=
\frac{\sum_k w_k |d_k(X_R)-d^{target}_k|}{\sum_k w_k}.
\]

既定は5属性を等重みとする。値の範囲は0〜1。
属性名は `s_tech, s_indep, s_hand, s_foot, s_move`。
`s_rhythm`は参考値だけを返し、目標ベクトルにも誤差にも含めない。
6番目の境界は参考クラスを再現するため読み込む。

原譜と候補は**同じ直前小節**を文脈にして再計算する。直前小節がなければ明示的に`None`。
将来の小節連続編集では、確定済みの直前小節を渡す必要がある。
直後の小節の難易度が変わる影響は、今回の単一小節採点には含めない。

クラスは相対的な順序尺度で、心理的難易度の等間隔を実証した値ではない。
同じクラス内の小さな変化はこの誤差に現れず、クラス境界で不連続になる。
0.2などクラス刻みに一致しない目標では、到達可能な候補でも誤差0にならないことがある。
連続値への別の正規化は追加せず、まず承認済みラベルとの整合を優先した。

### 骨格保持

1小節96位置で以下を比較する。Ghostを含むSnareの弱い打点も、低い重みで系列に残す。

| 成分 | 打点系列の値 | 成分間の相対重み |
|---|---|---:|
| Kick | 拍頭2、その他1 | 0.45 |
| Snare／Rim | 第2・第4拍頭3、その他1 | 0.45 |
| Accent | 明示されたAccent位置1 | 0.10 |
| Fill境界 | 明示区間の実打撃の最初・最後を別々の系列に記録 | 0.10 |

各成分は `Dice(a,b) = 2 sum(min(a,b)) / (sum(a)+sum(b))`。
使用できる成分だけで相対重みを正規化して加重平均する。
両方に打点がない成分は除外する。Fill区間は原譜の明示注釈を基準にする。
候補が注釈を書き換えて有利な採点区間を選ぶことは認めない。

全成分に証拠がない場合は加点0とし、満点1を与えない。これは「非類似」と断定する意味ではない。
打点がない成分は内訳で`null`、有効重み0として区別する。
Aメロ・サビなどの楽曲構成は現在の入力から確認できないため、推測して加点しない。
この骨格指標は本研究の操作的定義であり、主観的類似度の正解ではない。

### ルール数

`N_rules`は現在の候補へ至るまでに、実際に適用した編集ルールの数。
非適用・拒否のルールは数えない。現段階の採点APIでは呼び出し元が非負整数で渡し、
後続のBeamSearch実装が履歴から管理する。
同じ最終譜面に2ルールと3ルールで到達した場合、既定では2ルールの方を0.02高く採点する。

### 編集距離

音符の内容を `(位置, 楽器, 強弱, 奏法)` とする。
同じ内容の音符を多重集合として相殺し、残った原譜音符数をA、候補音符数をBとする。

\[
L_{\mathrm{edit}}=\frac{\max(A,B)}{\max(1,N_{original})}.
\]

残りを可能な限り置換し、余った分を追加・削除する最少編集数に相当する。
置換・追加・削除は各1。音符IDや格納順、注釈だけの変更では距離が増えない。
大きな移動も1置換と数えるため、移動量そのものの細かい距離ではない。
大幅追加では1を超えることがあり、クリップしない。

ステップ1の安全制約は、原譜のIDに基づく保護と累積編集数を引き続き使用する。
採点用の編集距離は最終譜面内容の比較であり、適用制約の編集履歴とは区別する。

## ハード制約

ステップ1の保護音・BPM・拍子・小節長・同時演奏・重複・編集上限を先に検査する。
さらに、元のFill注釈の変更、現在のstandard語彙に表現できない候補、非有限の難易度を不適格にする。
高い骨格係数などによって違反を埋め合わせることはできない。

結果は`valid=false, total=null`と理由を返す。
探索で比較するときだけ`ranking_score=-inf`となる。JSONへ非標準のInfinityを保存しない。
不正な元譜面・設定・目標は候補不適格と区別して例外にする。

## 採点APIの入力

内部APIの目標は、**属性名付き辞書、0〜1の絶対値**として定義した。
配列順序の誤解を防ぎ、負値を暗黙に差分へ読み替えたりクリップしたりしない。
図の負値を含むベクトルや属性順序の違いを、外部入力でどう扱うかはステップ3で確認する。

```python
from src.arrangement.scoring import ScoringModel

model = ScoringModel(boundaries, vocabulary)
target = {
    's_tech': 1/7, 's_indep': 2/7, 's_hand': 3/7,
    's_foot': 3/7, 's_move': 0.0,
}
result = model.score(original, candidate, target, rule_count=2, previous=previous)
print(result.valid, result.total, result.contributions)
```

返り値には各属性の生スコア・クラス・正規化値・誤差、骨格成分と有効重み、ルール数、
編集距離、各項の寄与、拒否理由を含める。閾値を再推定する処理は含めない。
