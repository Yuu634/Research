# ステップ4：損失関数

損失を`src/beam_muse/losses.py`、離散譜面の採点を`evaluation.py`に分けた。

## 再構成とKL

`L_rec`は`X_after`の次トークンCross Entropy。入力は1トークン右にずらし、
語彙のPAD ID（今回の語彙では0）を除外する。PADしかない教師列は拒否する。
`L_KL`は対象小節の対角Gaussianと標準正規分布のKLで、バッチ平均後に
潜在次元ごとのfree bitsを適用する。文脈小節の潜在は文脈条件にだけ使う。

## 離散指標を学習へ反映する方法

既存の難易度v2はクラス化を含む離散計算なので、生成トークンのargmaxを
そのまま自動微分することはできない。難易度を予測する補助headだけを学習しても、
生成譜面の難易度改善を保証できないため、本実装では自己臨界方策勾配を使う。

1. 同じ入力から、文法制約付きの確率分布で1系列をsampleする。
2. 同じモデルのgreedy系列をbaselineとして生成する。
3. 両者の離散譜面を以下の指標で採点する。
4. 各成分について`(cost_sample - cost_greedy).detach() * log p(sample)`を最小化する。

コストがgreedyより大きい系列の確率を下げ、小さい系列の確率を上げる。
これは期待コストの勾配推定であり、コスト自体を微分可能な別指標に置き換えてはいない。

| 成分 | 定義 |
|---|---|
| difficulty | 原譜の前小節を文脈として再計算したv2の5属性MAE |
| skeleton | 原譜に対する固定重みの骨格類似度の`1−similarity`。証拠なしは0 |
| context | 原譜から変化した前後境界の距離。[ステップ5](BEAM_MUSE_STEP5_REVIEW.md)参照 |
| edit | 原譜からの音符編集距離を1で上限処理 |
| validity | 原譜の保護・編集制約に違反すれば1、それ以外0 |

出力未完了・難易度計算不可では全成分を1とする。
制約違反の出力でも算出可能な難易度・骨格・文脈のコストは計算し、
違反をvalidityで別途罰する。評価時には違反出力を成功に数えない。

学習の目的は以下の期待損失：

`L_rec + β L_KL + E[λ_d difficulty + λ_s skeleton + λ_c context + λ_e edit + λ_v validity]`

図の3補助項に加え、最小編集と保護制約の補助項を設定可能にした。
既定値は`β=.01, λ_d=1, λ_s=.5, λ_c=.2, λ_e=.1, λ_v=1`。
本規模のチューニング前の初期値であり、最良値とは扱わない。

sample生成は`no_grad`で行い、その確定系列のlog確率を1回の並列forwardで再計算する。
逐次生成の全計算グラフを保持せず、同じ文法マスク・温度1・dropout無効の方策を使う。
対象潜在はこの経路では平均値を使う。再構成経路はdropout・潜在samplingを有効にする。
補助損失は`risk_interval`ステップごとに計算し、係数を同間隔倍して補正する。
`risk_examples`で各対象バッチから採点する件数を制御する。

方策勾配の数値は負になることもあり、品質の絶対評価や早期停止指標には使わない。
sample/greedyの各コストと再構成・KLを`history.json`に分けて保存する。
高分散で計算コストも高いため、間隔・係数・学習率の調整が必要。

確認テストでは損失の符号、PAD除外、KL、sample時と再計算時のlog確率一致、
出力層・Encoder・骨格条件層への勾配を検証する。
