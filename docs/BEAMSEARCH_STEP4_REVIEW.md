## 評価の目的と確認用の基準

**目標難易度への一致と骨格保持を同時に満たした入力の割合**を中心に評価する。
難易度だけ、骨格だけの結果も併記し、無編集と比較する。

| 指標 | 定義・向き |
|---|---|
| 難易度MAE | 5属性それぞれの目標との絶対誤差を等重みで平均。小さいほどよい |
| 属性別誤差・最大誤差 | 平均値で隠れる特定属性の不一致を確認 |
| 厳密一致率 | 全5属性の誤差が数値誤差`1e-12`以下の割合 |
| 目標到達率 | 全5属性の誤差がそれぞれ`0.5/7`以下の割合 |
| 1クラス以内率 | 全5属性の誤差がそれぞれ`1/7`以下の割合。補助指標 |
| 難易度改善量 | 無編集のMAE − 出力のMAE。正なら目標へ接近、負なら悪化 |
| 骨格類似度 | 固定のKick・Snare・Accent・明示Fill境界の重み付きDice。大きいほどよい |
| 同時達成率 | 適格な出力で、全属性が半クラス以内かつ骨格類似度0.90以上の割合 |
| 適格出力率 | 保護・演奏制約・語彙・難易度算出などの検査を通った割合 |
| 無編集率 | 適格出力のうち音符内容が元譜と同じ割合 |
| 編集距離・音符数差・ルール数 | 同程度の達成度で、どの程度の編集を必要としたかを確認 |
| 実行時間 | 平均・中央値・最大値と測定数。測定区間を明記 |

`0.5/7 ≈ 0.071429`は、v2正規化クラスの半クラス幅。
目標がクラス刻みに一致するペアデータでは、半クラス以内とクラスの厳密一致は同じ判定になる。
連続値目標では近いクラスを許容する。平均誤差だけによる合格判定は行わない。

**半クラスと骨格0.90は、今回の確認用に置いた研究上の基準であり、
人間の知覚や演奏上の許容範囲を実証した閾値ではない。**
`EvaluationConfig`で指定できるが、比較実験ではモデルごとに変えず、事前に共通値を固定する。

## 探索スコアとの関係

ステップ2の探索スコア`J`はルール列を探すための目的関数。
今回の性能比較では、モデルごとに係数が異なる`J`の大小を評価値に使用しない。

- 評価の難易度誤差は常に5属性の等重み。
- 骨格成分の相対重みはKick 0.45、Snare 0.45、Accent 0.10、Fill 0.10で固定。
  両方に打点のない成分を除き、有効成分で正規化する。
- 探索用の難易度重み・骨格重み・4項の係数を変更しても、同じ出力の評価は変わらない。
- 同じ譜面へ2ルールと3ルールで到達した場合、難易度・骨格の評価は同じ。
  ルール数は効率の指標として別に記録する。

骨格の定義そのものは探索時と共通であるため、これは最適化目標に沿った動作の評価であり、
独立した人間の音楽的評価ではない。保護音の保持もルールの制約で保証する部分がある。
これだけで編曲全体の自然さ・演奏しやすさ・主観的骨格保持を実証したとは扱わない。
演奏者による主観評価は未実施。

### 増減・保持したい属性の診断

元譜の正規化値を`b_k`、目標を`t_k`、出力を`a_k`とする。

- 増減指定のある属性：`|t_k − b_k| > 1e-12`。
- 方向一致：増加希望なら`a_k > b_k`、減少希望なら`a_k < b_k`。
  無変化は方向一致に含めない。
- 属性別接近：`|a_k − t_k| < |b_k − t_k|`。
  希望方向へ動いても、大きく行き過ぎた場合は接近とは判定しない。
- 保持属性の変動：`t_k = b_k`の属性について`|a_k − b_k|`を平均。

方向一致率と属性別接近率は、まず各出力の増減指定属性内で平均し、出力間で平均する。
増減指定のない出力の方向指標は`null`とし、分母に含めない。
保持属性がない場合の保持変動も同様。属性ごとの真偽値・差分はJSONに保存する。

## 失敗・欠測・集計単位

評価APIは1入力につき1出力を受け取る。
出力なし・タイムアウトなどは`candidate=None`と理由を渡し、行を削除しない。

| 出力状態 | 成功率の分母 | MAEの扱い |
|---|---|---|
| `valid`：適格 | 含める | 再計算したMAE |
| `invalid`：保護違反・語彙外など | 含める。成功は偽 | 適格出力平均から除外し、失敗補正MAEでは1 |
| `failed`：出力なし | 含める。成功は偽 | 同上 |

**失敗補正MAE**は、失敗を正規化MAEの最大値1として全入力で平均する。
これは失敗時の実際の難易度を推定するものではなく、失敗を除外して有利になるのを防ぐ規約。
適格出力だけのMAEも、件数を添えて別に報告する。
評価入力自体が不正な場合はAPIがエラーにする。将来の評価集合は事前に検証し、
除外する必要がある入力はモデル共通の条件と理由を記録する。

骨格の全成分に比較材料がない場合、骨格類似度は`null`とし、同時達成に含めない。
成分ごとの平均にはそれぞれ件数を付ける。Fillが不明なら高得点を与えず、平均の分母から外す。
空の評価集合の率・平均は`null`。出力が全て失敗なら成功率0、適格出力MAEは`null`。

小節数の多い曲だけが評価を支配しないよう、次の両方を保存する。

1. 全入力を等重みとする小節単位の平均・成功率。
2. `source_id`で曲ごとに平均し、曲を等重みにするマクロ平均。

曲単位でも無出力を除外しない。曲ごとの件数・値も保存する。
この集計自体は信頼区間や統計的有意差を算出しない。
重複`case_id`や異なる評価閾値が同じ集計に混ざる場合はエラーにする。

### 実データによる集計確認

train先頭32ペア・10曲を使用。無編集と、固定の「HH間引き→Ghost削除」を比較した。
適用不可・拒否のルールは無変更として次へ進み、実際に適用されたルールだけを数えた。

| 診断用の方法 | 適格出力 | MAE | 同時達成 | MAE改善 | 無編集 |
|---|---:|---:|---:|---:|---:|
| 無編集 | 32/32 | 0.100893 | 0/32 | 0/32 | 32/32 |
| 固定2ルール列 | 32/32 | 0.096429 | 1/32 | 2/32 | 30/32 |

閾値をこの結果に合わせて変更していない。今回val/test/itestで性能比較は行っていない。

## 次段階での比較・選定方針案

同一入力集合・同一評価閾値・同一難易度境界・同一保護条件で、探索幅・深さ・係数を比較する。
無編集と固定ルール列を比較対象に含める。
候補選定はvalで、**曲単位の同時達成率を第一指標、失敗補正MAEを第二指標**とする案。
同等の場合は編集量・ルール数・時間を参照する。
test/itestは選定後の最終評価に使用し、候補や閾値の調整に使用しない。
