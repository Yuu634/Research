入力の小節は4/4・1拍24位置・1小節96位置に限定する。テンポと拍子をルールで変更しない。
音符には安定したIDを付け、削除・追加・位置移動・楽器変更の対応を追えるようにした。
原譜は不変で、編集は新しい小節を返す。

既存v2の `Hit.special` は詳細な奏法を一つのフラグへまとめるため、編集表現にはそのまま使わない。
今回の表現はHIT、FLAM、ROLL、RIMSHOT、XSTICK、CHOKE等を区別し、
装飾音のグループと主打／副打、明示されたFill区間を別途保持する。
既存のv2算出式、データ、基準YAML、モデル、データローダーは変更しない。

## 今回具体化したルールの意味

1. **割合の意味**：`reduce_ghost_note_ratio(r)`はGhost数の`floor(N*r)`打を削除する指定。
   `reduce_kick_density(r)`と`reduce_hand_roll_density(r)`は`ceil(N*r)`打を残す指定。
   保護音は削除せず、実際の編集数を返す。rは0〜1。
2. **時間の単位**：`limit_*_min_interval(t)`のtは秒。その他の位置・間隔パラメータは96位置グリッド単位。
   120 BPMでは1位置＝約20.83 ms、240 BPMでは約10.42 ms。
3. **連打の認識**：16分→8分、32分→16分は、対象楽器群で対応する間隔が4打以上続く区間に適用する。
   不規則な並びを勝手に等間隔の連打として扱わない。8分→16分や4分→3連符は既存の連続区間に追加する。
   3連符の位置間隔は8。小節をまたいだ追加や位置の折り返しは行わない。
4. **Roll・Flam・Drag**：明示された奏法・装飾音グループだけを対象にする。
   単一FLAM/ROLLトークンは通常HITへ変える。明示された副打があれば削除する。
   近接する通常打撃から奏法を推定しない。Dragは現在の標準語彙にないため、注釈付き内部表現で扱う。
5. **区間を追加するルール**：Roll、Kick3連符、ダブルバス、交互系列、ポリリズム追加は
   `start`・`end`の明示指定を要求する。半開区間であり、指定がなければ適用しない。
6. **Fill**：`simplify_tom_fill`と境界保護は、外部から与えたFill区間を使う。
   区間がなければFillを推測して編集しない。境界保護は区間内の最初・最後の実打撃を対象にする。
7. **同期化・ポリリズム**：`remove_syncopated_kick`は非拍頭Kickを最寄り拍頭へ寄せる代理ルール。
   音楽的シンコペーションの認識器ではない。`reduce_limb_polyrhythm`は手・足の両群が
   明示的な等間隔で、周期が異なり倍数関係でない場合に共通8分格子へ寄せる。
   左右それぞれの運指やポリリズム全般を推定する機能は含まない。
8. **同位置への衝突**：一般の移動・楽器置換で同時刻・同楽器が重なれば候補を拒否する。
   共通格子への簡略化だけは、保護音優先で代表音を残し、他の音を削除として明示計上する。
9. **移動距離**：v2と同じ配置距離表を使う。Tom2は`tom_mid`に対応させる。
   近接打点への置換は前後の異なる時刻の手打点を参考にするが、実運指を推定したものではない。
   `reduce_tom_span`はHigh/Mid Tomに範囲を制限するため、個々の移動距離が必ず減るとは限らない。
10. **Rimの区別**：`SNARE_RIM`はGM 37由来なのでCross Stickの置換対象にし、
    Rimshotの置換対象は明示された`RIMSHOT`奏法だけとする。

ルール名が「簡略化」でも、実測する5属性がすべて下がるとは限らない。
難易度・骨格・編集量の総合判定は、確認後のステップ2で扱う。

## 既定の骨格・安全制約

- 拍頭のKick、第2・第4拍頭のSnare、各拍頭の主要打撃を保護する。
  主KickのIDは明示指定も可能。主要打撃はAccent、Backbeat、拍頭Kick等の優先順位で選ぶ。
- Accentの削除・弱化・位置変更を禁止する。ルールの候補編集ではAccentを保守的に変更対象から外す。
- 明示されたFill区間の開始・終了打撃を保護する。
- BPM・拍子・小節長を固定し、小節外の音、同位置・同楽器の重複、3打以上の手の同時演奏を採用しない。
- 既定の追加上限は8打、削除上限は16打、編集率上限は50%。
  位置移動・楽器変更・強弱変更は同じIDの変更として1編集に数える。
  編集率は `(追加 + 削除 + 変更) / max(1, 元音符数)`。

これらは今回の初期設定で、演奏可能性や音楽的妥当性を保証するものではない。
保護が優先されるため、指定した残存割合・最小打撃間隔が必ず達成されるわけではない。
違反候補は部分的に採用せず、適用前の小節と拒否理由を返す。
後続の連続適用では常に最初の原譜を`original`へ渡し、累積編集制限を確認する。

```python
from src.common.representation import from_tokens
from src.beamsearch.rules import apply_rule
from src.common.safety import default_guards

original = from_tokens(tokens)  # standardの文字列トークン、単一小節＋EOS
guards = default_guards(original)
first = apply_rule(original, 'hh_16_to_8', original=original, guards=guards)
second = apply_rule(first.after, 'remove_ghost_notes', original=original, guards=guards)
print(second.status, second.reason, second.cumulative_edits)
```

`rules.py`内の個別関数は候補生成用の純粋関数であり、安全な適用入口は`apply_rule`。
状態は`applied / unchanged / rejected`で、適用不能な奏法・区間の理由も残す。
パラメータ不正は例外として返し、適用不能と混同しない。

standardへの書き戻しでは語彙集合を指定すると、語彙外の奏法・強弱を検出できる。
例えばTomへの明示的なGhost副打は現在の語彙に存在しない場合がある。
また、装飾音グループとFill注釈はstandardだけでは保存できないため、内部表現／JSONを保持する。
探索入力・出力として許す表現範囲はステップ3で確認する。

## 検証結果

- 新規86テスト成功。65編集ルールすべてについて、変更例・決定性・原譜不変性・安全制約を検査。
- v2算出式・ペアデータ・トークン方式の関連53テスト成功。合計139件成功。
- CLIの`--help`成功。
- 3データセット各10曲、計30曲90小節で実データのトークン往復を検査。
  音符・奏法・強弱・BPMの保持を確認。HH16分→8分は27小節で適用、63小節は変更なし。
- 全65ルールの人工例と、編集前・単体編集後・既定制約付き編集後のMIDI195ファイルを生成。
  MIDIは全件4/4・1小節長、note-on/off数の一致、ドラムチャンネルを確認。
- 人工例の既定制約付き結果は24ルール適用、5ルール変更なし、36ルール拒否。
  編集内容が大きく見える例を選んだ結果であり、実譜面での採用率ではない。

既存ローダーの難易度整合テスト2件の既知の失敗は、本変更の対象外。
