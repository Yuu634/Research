作成日：2026-10-01。ブランチ：`linear-06/beamsearch`。
ステップ4のコミット`0184d1f`後、ユーザーの続行指示を受けて実装した。
**状態：ステップ5完了。6候補のval比較・選定後のtest/itest評価・再開時の検証を終え、ステップ6でpushする内容を確定した。**

## 実装した探索

- 原譜・目標・前小節・保護情報はステップ3の入力契約を継続。
- 65編集関数と引数違いを合わせた79アクションを共通ライブラリとして使用。
- 各深さで全アクションを適用し、適格候補のスコア上位を次の探索対象に残す。
- **直前よりスコアが下がった候補も探索幅の範囲で保持する**。
  最終結果は無編集を含む、全深さで見つかった最も高いスコアの候補。
- 保護・編集上限は常に原譜を基準に適用。語彙外・難易度算出不可の候補も除外する。
- 状態の重複判定は、位置・楽器・強弱・奏法だけでなく音符ID・注釈も含む。
  注釈が後続ルールの適用可能性を変えるため、音だけ同じ状態を一律にまとめない。
- 同じ深さの同一状態は1つにまとめ、既に展開した同一状態へ戻る経路を除外する。
  保留から落ちた未展開状態は、別経路から再度候補になることがある。
- 同点ならルール数、編集距離、ルール名・引数の辞書順で決定する。
- 不適用・拒否は適用ルール数に数えない。試行回数には含める。
- 深さ、ルール試行上限、新規候補なしのいずれかで終了する。
  探索幅が有限のため、全ルール列に対する大域的最適性は保証しない。

アクション追加の引数違いはGhost削除率、Kick保持率、手・足の最小打撃間隔、
手足の共通グリッド、手足打点を揃える許容幅。
区間が必要な6種類の追加ルールには、最終拍`[72,96)`を明示指定する。
これは固定の編集対象区間であり、Fillと推定しているのではない。
Fill簡略化や装飾音グループを必要とするルールは、明示注釈がなければ不適用となる。

1入力の内部だけで難易度計算をキャッシュする。入力をまたいで文脈を混同しない。
入力・設定・実装・語彙・境界・データシャードのハッシュを記録し、
比較実験はバッチ単位で保存・再開できる。

## 固定した比較候補

全候補でアクション、保護条件、v2境界、評価閾値、対象入力を共通にした。
上限は1入力につき5,000ルール試行。

| 候補名 | 探索幅 | 最大深さ | 難易度係数 | 骨格係数 | ルール数係数 | 編集量係数 |
|---|---:|---:|---:|---:|---:|---:|
| `beam1_d1` | 1 | 1 | 1 | 0.5 | 0.02 | 0.1 |
| `beam4_d2` | 4 | 2 | 1 | 0.5 | 0.02 | 0.1 |
| `beam8_d3` | 8 | 3 | 1 | 0.5 | 0.02 | 0.1 |
| `beam8_d3_target` | 8 | 3 | 2 | 0.5 | 0.02 | 0.1 |
| `beam8_d3_skeleton` | 8 | 3 | 1 | 1.0 | 0.02 | 0.1 |
| `beam8_d3_light_edit` | 8 | 3 | 1 | 0.5 | 0.005 | 0.025 |

比較対照は無編集と固定「HH間引き→Ghost削除」。
候補・閾値は本比較の開始前に固定した。train先頭16件は実行確認だけに使用した。
`J`の係数をパラメータ比較で選び、ニューラルネットワークの重み学習は行っていない。
擬似ペアには正解の最適ルール列`R*`がないため、図の教師ルール列を作ったと扱わない。

## 選定と評価の手順

1. valの全ペアを共通条件で入力検証し、理由付きの除外一覧を保存。
2. 適格な同じ入力集合で6候補と2対照を評価。
3. 曲単位同時達成率が最大のBeamSearch候補を選ぶ。
4. 同率の場合は曲単位の失敗補正MAE、編集距離、ルール数、平均時間、候補名の順で比較。
5. 選定設定をJSONに保存してから、test/itestを選定モデルと2対照で評価。
6. 保存した選定モデルの全出力について、履歴の再生と評価値の再計算を検証。

同時達成条件は、全5属性が目標の半クラス以内、骨格類似度0.90以上、制約違反なし。
探索スコアの係数で評価基準を変更しない。
不適格な入力の除外と、探索による違反出力・出力失敗は別に記録する。
後者は評価分母に含める。無編集へのフォールバックも評価対象に残す。

## 実験結果

### valでの選定

val 5,429ペアのうち、共通の入力検証を通った5,406ペア・1,137曲を使用した。
除外23ペアは全て、後小節に同位置・同楽器の重複打点があるため。
後小節は採点に使わないが、ステップ3で承認済みの入力検査では拒否する。
除外による適用範囲の制限を含む結果として扱う。

| 方式 | 曲単位同時達成率 | 小節単位同時達成率 | 曲単位MAE | 骨格類似度平均 |
|---|---:|---:|---:|---:|
| 無編集 | 0.00% | 0.00% | 0.108810 | 1.000000 |
| 固定HH間引き→Ghost削除 | 0.92% | 0.80% | 0.109927 | 0.998850 |
| `beam1_d1` | 26.61% | 23.68% | 0.063508 | 0.994764 |
| `beam4_d2` | 29.12% | 26.79% | 0.059751 | 0.994500 |
| `beam8_d3` | 30.13% | 27.86% | 0.058555 | 0.994469 |
| **`beam8_d3_target`** | **36.34%** | **33.98%** | **0.050476** | **0.989346** |
| `beam8_d3_skeleton` | 27.78% | 25.49% | 0.061090 | 0.996616 |
| `beam8_d3_light_edit` | 35.24% | 33.74% | 0.050765 | 0.991248 |

**選定モデルは`beam8_d3_target`：探索幅8、最大深さ3、
`J = −2.0 L_difficulty + 0.5 S_skeleton − 0.02 N_rules − 0.1 L_edit`。**
第一指標で一意に最良であり、時間による同率判定は使用しなかった。
標準係数より目標難易度への一致を重視する設定が、今回のvalで良い結果となった。

### 選定後の最終評価

testは6,713ペア中6,697ペア・1,299曲、itestは76ペア・57曲を使用した。
testで除外した16ペアも全て後小節の重複打点が原因。itestの除外は0。

| 分割 | 方式 | 曲単位同時達成率 | 小節単位同時達成 | 曲単位MAE | 骨格類似度平均 | 無編集率 |
|---|---|---:|---:|---:|---:|---:|
| test | 無編集 | 0.00% | 0/6,697（0.00%） | 0.111672 | 1.000000 | 100.00% |
| test | 固定HH間引き→Ghost削除 | 0.79% | 46/6,697（0.69%） | 0.112048 | 0.999672 | 90.89% |
| test | **選定BeamSearch** | **36.24%** | **2,042/6,697（30.49%）** | **0.052246** | **0.987993** | **40.33%** |
| itest | 無編集 | 0.00% | 0/76（0.00%） | 0.133960 | 1.000000 | 100.00% |
| itest | 固定HH間引き→Ghost削除 | 2.92% | 3/76（3.95%） | 0.111404 | 0.998648 | 67.11% |
| itest | **選定BeamSearch** | **38.89%** | **30/76（39.47%）** | **0.039808** | **0.981305** | **25.00%** |

全方式の適格出力率は100%。これは原譜が入力検査を通り、探索で制約を守り、
適切な変更が見つからないときには原譜を返す構成による。
**適格性100%は、目標難易度への到達100%を意味しない。**
選定モデルの平均探索時間は、24プロセス並列時でtest 0.514秒、itest 0.467秒／入力。

今回の指標では固定2ルール列より目標に近づける一方、
testの約7割では「全5属性の目標到達と骨格0.90以上」の同時達成に至らなかった。
特に40.33%が無編集であり、強い保護制約・ルールの適用範囲・有限の探索・スコアの兼ね合いにより
編集を選べないケースが残る。個別の原因比率をこの集計だけから断定はしない。
itestは76ペアと少ないため、その値を広い楽曲集合へ一般化しない。
統計的有意差や信頼区間は今回算出していない。

testでは3,996/6,697件で無編集よりMAEが改善し、MAE悪化は0件だった。
ただし、173件では少なくとも1属性が元譜より上がり、169件では音符数が増えた。
目標は5属性の総合的な一致であり、各属性や音符数の単調な減少は制約にしていない。
難→易の目標でも追加・配置変更のルールが選ばれることがある。
個々の属性を必ず下げる用途には、現状の総合スコアだけでは保証が足りない。

## 実装・実行方法

| ファイル | 用途 |
|---|---|
| `src/arrangement/beam_search.py` | アクション集合・探索・履歴・予算・候補検査 |
| `src/arrangement/selected_model.py` | 選定設定と対応メタデータの復元 |
| `config/beamsearch_candidates.json` | 6候補と固定の評価閾値 |
| `config/beamsearch_selected.json` | 選定済みの推論用パラメータ設定 |
| `scripts/evaluate/compare_arrangement_models.py` | 並列比較・val選定・選定後のtest/itest評価・再開 |
| `scripts/evaluate/report_arrangement_comparison.py` | 履歴と指標の再検証、比較表、確認用譜面・MIDI |
| `scripts/generate/arrange_beam_search.py` | 選定モデルによる単一小節の編曲CLI |

リポジトリ直下から実行する。

```bash
# trainの少数例で動作確認。本評価とは出力先を分ける
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m scripts.evaluate.compare_arrangement_models \
  --phase smoke --workers 4 --limit 16 --output output/beamsearch_smoke_new

# valで選定し、設定を固定してからtest/itestを評価
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m scripts.evaluate.compare_arrangement_models \
  --phase all --workers 24 --output output/beamsearch_step5

# 再検証と確認資料、推論用設定の出力
python -m scripts.evaluate.report_arrangement_comparison \
  --export-model config/beamsearch_selected.json

# ステップ3で作成した入力例から編曲
python -m scripts.generate.arrange_beam_search \
  --input output/beamsearch_step3/absolute_request.json \
  --output output/beamsearch_step5/inference_example
```

比較CLIは`--phase select`でvalまで、`--phase test`で固定後のholdoutだけも実行できる。
本評価では`--limit`による切り詰めを行わない。`--limit`はsmoke専用。
再開時に実装・設定・入力が異なる場合はエラーとし、別の出力先を指定する。
並列数は再開時に変更できるが、実行記録JSONには含めていないため、時間の比較条件として別途記録する必要がある。
時間は探索・固定ルール適用の区間で、読込・入力検証・評価計算は除く。
全候補を同一機械で24プロセス並列実行した条件の値であり、単独実行の応答時間ではない。

推論CLIは選定時の語彙と境界のハッシュ一致を確認する。
`result.json`にはstandardトークン、IDを保持した音符、適用履歴、スコア内訳、評価値を保存。
HTMLと入力・出力MIDIも生成する。MIDIは強弱・位置・楽器の試聴用で、
奏法専用音源のアーティキュレーションを再現するものではない。

評価結果・譜面・MIDI・バッチ・入力キャッシュは`output/`以下に保存し、Gitには含めない。
パラメータ設定・実装・テスト・本確認資料を管理する。基準YAMLと既存チェックポイントは変更しない。

## 解釈上の範囲

- 選定結果は、比較した6候補の中でvalの固定指標が最良という意味。
- 評価は既存の擬似ペアの`d_after`を条件とする。教師譜面の`X_after`は探索に渡さない。
- 元データのペアは難→易であるため、実データでの難化・増減混在の性能を示すものではない。
  難化ルールを選べることは人工例の回帰テストで確認する。
- 難易度・骨格とも本研究の操作的定義を使う。主観的な自然さ・弾きやすさの人手評価は未実施。
- 拍子・小節長・主要打点を保護する単一小節の編集に限定する。
  他トラックとの整合、前後を含む曲全体の編曲品質は今回評価していない。
- 不明なFill・装飾音・曲区間を推測して補っていないため、その情報を要するルールの適用機会は限られる。
