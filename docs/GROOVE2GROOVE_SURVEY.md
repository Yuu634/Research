# Groove2Groove の収録譜面とドラム学習への適合性

調査日: 2026-09-29。以下は選定前の調査記録。同日、ユーザーが採用を決定した。公式 v1.0.0 の説明、スタイル表、配布アーカイブと MIDI サンプルを調査した。

## 結論

Lakh MIDI + Groove MIDI に加える、**伴奏スタイルの多様性を補う合成データ**として候補になる。
人の演奏、難易度の正解ラベル、簡単版と難しい版の対応譜面が得られるデータとは区別する。
特に現行トークナイザーでは、コンガなどの未対応打楽器が失われる。採用時はドラムセットと追加パーカッションの取り扱いを決める必要がある。

## 生成方法と譜面の構成（公式情報）

[公式サイト](https://groove2groove.telecom-paris.fr/)によると、コード進行から Band-in-a-Box で生成した伴奏 MIDI である。
同じコード進行を複数スタイルで伴奏化した並列コーパスであり、有名曲の完成譜をそのまま収集したものではない。
コード進行は iRb コーパスで学習した言語モデルから生成され、長調と短調がおよそ5:1。

ベース、ピアノ、ギター、ストリングス、ドラムを含むマルチトラック構成が用意されている。
[公式前処理](https://github.com/cifkao/groove2groove/blob/master/data/synth/prepare.sh)もこれらの楽器を分離している。
全ファイルですべてのパートが鳴るわけではなく、空トラックや本編のドラムがないファイルもある。
コード譜は ABC と Band-in-a-Box の MGU 形式でも付属する。

「約3,000スタイル」は1,476の基本スタイルに A/B セクション用のサブスタイルを組み合わせたもの。
A/B は簡単・難しいという難易度ラベルではない。同じコード進行の組も、ドラムの音符が対応する難易度変換ペアとは保証されない。

## ファイル規模と公式分割

件数はアーカイブ全体を走査して確認。長さと分割の意味は[公式配布説明](https://zenodo.org/records/3958000)による。

| 分割 | raw | fixed | 本編の長さ | 分割の意味 |
| --- | ---: | ---: | --- | --- |
| train | 5,744 | 5,733 | 252小節/ファイル | 2,872サブスタイル、各2ファイル。raw の11件は空 |
| val | 1,200 | 1,200 | 16小節/ファイル | 40サブスタイル、各30ファイル |
| test | 1,200 | 1,200 | 16小節/ファイル | 40サブスタイル、各30ファイル |
| itest | 1,200 | 1,200 | 16小節/ファイル | train に現れる40サブスタイル。コード進行は test と共通 |
| 合計 | 9,344 | 9,333 | — | ドラム抽出後の利用可能件数とは異なる |

先頭に2小節のカウントインがある。`fixed` は空ファイルを除き、楽器のプログラム番号を修正した版。
raw/fixed を別々の学習例として混ぜない。train/val/test のスタイル集合は分離され、A/B は同じ分割に入る。
itest は既知スタイルへの評価であり、未知スタイルの test と性質が異なる。

## MIDI の実測（全件ではなく256件）

各 fixed 分割からファイル名の SHA-256 が小さい64件を選択。合計256件を解析し、解析エラーは0件。
ドラム判定は MIDI チャンネル10（ライブラリ上は9）で、先頭8四分音符分をカウントインとして除外した。
サンプルはすべて4/4だった。全件への割合推定やスタイル均等抽出ではなく、再現可能な内容確認である。

| 分割 | 調査件数 | 本編ドラムあり | 未対応ピッチを含むファイル |
| --- | ---: | ---: | ---: |
| train | 64 | 63 | 35 |
| val | 64 | 61 | 22 |
| test | 64 | 64 | 33 |
| itest | 64 | 62 | 32 |
| 合計 | 256 | 250 | 122 |

- MIDI は256件すべて9トラック、120 ticks/四分音符、テンポ120 BPM、拍子メタ情報4/4。
- スタイル表が12/8の `BEEBSLO` のサンプル6件も、MIDI メタ情報は4/4だった。スタイル分類から MIDI 拍子を決め打ちしない。
- `BB Drums` のトラック名は256件すべてにあったが、6件にはカウントイン後のドラム音符がなかった。名前の有無だけで採否を決めない。
- 本編ドラム音符は合計423,877。ベロシティは3〜127で、強弱を含む。
- 現行 `DRUM_NOTE_MAP` の未対応音符は146,175（34.49%）。長い train ファイルの影響を受けるサンプル内の音符割合で、データ全体の比率ではない。
- 未対応にはハンドクラップ39、ボンゴ60/61、コンガ62/63/64、カバサ69、マラカス70などがある。GMの一般的な35〜81の範囲外もあり、31・82・87等を推測で変換しない。
- 1四分音符を24分割したグリッドから外れる音符は37,117（8.76%）。単純な除去ではなく量子化前後の差を記録する。
- ドラムのある train サンプル63件で、音符の開始位置とピッチだけを比較した小節パターンの種類数は中央値26、範囲12〜109。252小節がすべて別パターンというわけではない。ベロシティ・音長はこの比較に含めていない。

タイミングの細かなずれや強弱があっても、人がその MIDI を生演奏したことを意味しない。
また、メタデータ上のスタイル推奨速度と実 MIDI の120 BPMが異なるため、実演速度の多様性を得る用途には追加の設計が必要。

### 実際に含まれるパターンの例

いずれもカウントインを除いた最初のドラム小節を確認した例。ジャンル全体に一般化しない。

| サンプル | 確認した内容 |
| --- | --- |
| `itest/fixed/maj812.J!TRAD_b.mid` | ジャズ。1・3拍目にキック、2・4拍目にスネア。ハイハットの裏拍が約2/3拍後に置かれるスウィング系 |
| `itest/fixed/maj835.R_PRINZ_b.mid` | ファンク。16分音符相当の位置にキック・スネア・ライド/ベルが組み合わされ、微小なタイミングずれを含む |
| `itest/fixed/maj727.C_TIM_b.mid` | カントリーロック。16分ハイハットを中心に2・4拍目のスネア、裏拍のキック、タムを含む |
| `itest/fixed/min174.MerSlow_b.mid` | ラテン/メレンゲ。キック・ハイハットとコンガ62/63/64が共存する。現行語彙ではコンガが落ちる |
| `itest/fixed/maj886.ROCK8_2_a.mid` | ロック。キック・スネア・ハイハットにライドベル、カウベル、コンガも重なる。ドラムセットだけの単純なロック譜ではない |

複数パーカッションの同時演奏は、単独ドラマーの手足で演奏可能な譜面とは限らない。
難易度評価では「音符が多い＝難しい」と処理する前に、対象楽器と演奏人数の想定を揃える。

## 本研究での利用案

以下は調査に基づく提案であり、調査後にユーザーが採用を決定した。実装方針は [収集手順](DATA_COLLECTION.md) を参照。

| データ | 想定する役割 |
| --- | --- |
| Lakh MIDI | 実楽曲由来の長い構成・編曲からドラムを収集 |
| Groove MIDI | 人の演奏のタイミング・強弱と、その評価 |
| Groove2Groove | 合成伴奏のジャンル・フィールの幅を補い、スタイル別の生成傾向を検証 |

Groove2Groove は補助学習データ、および合成スタイルへの汎化を測る追加評価として有用と考える。
人の演奏に対する品質評価は Groove MIDI 等と分けて報告する。収録説明からは難易度の人手正解ラベル、beat/fill ラベル、難易度違いの対応譜面は確認できなかった。

採用時の処理案:

1. fixed を使用し、カウントインを除外して本編ドラムの有無を検証する。
2. 抽出 MIDI には原ピッチ・強弱・タイミング・テンポを残す。ドラムセット用の語彙制限やパーカッション拡張は別工程にする。
3. スタイル、サブスタイル、コード進行ID、公式分割、フィール、元テンポ、スタイル推奨テンポを別フィールドで保存する。
4. train/val/test を保持し、itest を train と混ぜない。同一コード進行や抽出後ドラムの重複・近似重複を別途確認する。
5. 同じファイル由来の小節断片を別分割に振り分けない。ドラム抽出によって失われた楽器の違いを、データ多様性として数えない。
6. 長い合成 train 譜面が学習を占めすぎないようにデータセット別のサンプリング量を調整し、追加の有無を比較する。
7. 公式前処理の8小節切り出しは参考になるが、`--force-tempo 60` は難易度研究へ無条件に持ち込まない。テンポ拡張をする場合も元データと区別する。

## 利用条件と再現方法

[Zenodo の公式メタデータ API](https://zenodo.org/api/records/3958000)で `metadata.license.id = cc-by-nc-4.0` を確認。
データは CC BY-NC 4.0 として配布されており、非商用条件を含む。研究利用時は公式論文も引用する。
コード側のライセンスとは区別し、混合集合でもデータセットごとの出典・条件を残す。

公式アーカイブ: `groove2groove-data-v1.0.0.tar.gz`、236,114,569 bytes。
取得後の MD5 `c407de7b3676267660c88dc6ee351c79` は Zenodo 公開値と一致。

```bash
python -m scripts.analysis.survey_groove2groove \
  --archive data/raw/groove2groove/groove2groove-data-v1.0.0.tar.gz \
  --samples_per_split 64 \
  --output data/metadata/groove2groove_research/audit.json

python -m pytest -q tests/test_survey_groove2groove.py
```

アーカイブを展開せず全ファイル数を数え、選択した MIDI をメモリ上で解析する。
`active_4quarter_bars` は4四分音符単位の集計であり、4/4以外への一般的な小節解析ではない。
`quarter_notes_after_count_in` は最終イベントまでの長さであり、終端イベントの位置によって公称小節長から少し短く/長くなる。
ドラムの指紋は開始時刻・ピッチ・強弱のみで、音長を含む完全な MIDI 同一性の判定ではない。

原アーカイブ・詳細 JSON・取得した公式メタデータは Git 管理対象外の `data/` に保存。
調査用 CLI はカウントイン除外、チャンネル判別、未対応ピッチ、グリッド判定、アーカイブ件数、抽出順序の再現性を2テストで確認済み。
採用決定後に行う全件のドラム抽出・トークン化・学習用分割検証は、このサンプル調査には含まれない。
